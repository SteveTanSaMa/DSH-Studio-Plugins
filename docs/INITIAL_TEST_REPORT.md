## 自动测试

`npm test`：5 项通过。

- 生成后保留精确版本、原始兼容声明及发布包证据。
- 上游不可达和 tarball 完整性失败均不覆盖上次完整 index/status。
- 下架条目阻止抓取与自动重新收录。
- 拒绝浮动版本及重复包名。
- 拒绝非 HTTPS、非指定 registry 和带凭据的来源，检查 SHA-512。

`npm run check`：两个条目通过官方 parseMarketIndex 校验，安装参数均为精确 npm 版本和明确 registry。

`npm run test:integration`：1 项复合端到端测试通过，覆盖以下真实行为：

- 本地 HTTP 直接提供本次生成的索引，官方 Host 通过真实 Worker 解析。
- 两个候选版本可选、兼容状态正确、安装目标精确。
- 中文与英文搜索、缓存复用、显式刷新。
- 拒绝 HTTP 重定向、无效索引、重复源及未配置源。
- 官方 Settings 保存源，重启后保留；另一临时 Profile 不继承；删除后重启不自动补回。
- 本地产生的无依赖 bundle 经真实 pnpm 下载与官方 Plugin Manager 安装；安装后默认停用，明确启用并重启后加载；停用后重启，再移除成功。

所有测试 Profile、包缓存和测试服务使用临时目录及 loopback 地址，结束时清理。没有修改 App/Runtime 仓库或用户已有 Profile。

## 私有阶段发布方式

源码和已生成预览存于私有 GitHub 仓库。Actions 在 push、PR、手动触发及每周一核验精确版本，成功时保存 14 天的私有预览附件。没有公网部署或匿名可用的索引 URL。

本机手工预览用 `npm run serve`，复制其临时 loopback 地址到同机的测试 Profile。GitHub 私有仓库 URL 本身不能直接用作官方市场源；当前读取器不提供私有仓库认证配置。

## 正式发布前剩余事项

1. 对两个候选做真实 Web UI、功能和 macOS arm64/x64 安装/卸载验收，再决定是否转为推荐。
2. 审核分类和说明，记录测试日期、App/Harness 版本与平台，避免把声明兼容当成功能验证。
3. 选择可公开读取、无重定向的 HTTPS 静态托管；索引仓库可继续私有，仅部署批准的产物。
4. 验证国内/海外网络、响应时间、完整目录切换、旧版恢复与撤回后的缓存更新。
5. 若增加 Studio 添加入口，复用官方源接口，保留其他源并尊重用户删除。

本轮建立的是技术验证基础；正式推荐源仍需内容与部署验收。
